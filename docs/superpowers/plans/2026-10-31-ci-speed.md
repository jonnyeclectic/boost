# CI speed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A typical PR's `ci` run finishes in about 30 min and its release publishes within minutes of the merge, while each PR's own core code is still held to 80% killed mutants.

**Architecture:** One planner job (`mutation-plan`) collects mutmut stats once, decides the mode (`none` / `diff` / `full`), and emits a JSON plan whose shards a variable matrix runs. PRs gate on mutants of changed `boost_cli/core` functions plus their direct callers; `main` skips re-proving a tree a green PR already proved, and a nightly `schedule` run of `ci` checks the whole codebase, whose red result turns the skip off.

**Tech Stack:** GitHub Actions, mutmut 3.8.0 (`mutmut.mutation.file_mutation`, `mutmut.stats`), pytest + pytest-xdist + pytest-cov, diff-cover, Python 3.12+ stdlib scripts.

**Spec:** `docs/superpowers/specs/2026-10-31-ci-speed-design.md` (approved 2026-10-31: option B with the red-nightly fallback; old survivors in changed functions count).

## Global Constraints

- Work in a worktree branched from `origin/main`, one branch per PR below; never in `/Users/jonny/Code/IdeaProjects/boost`.
- Every merge to `main` cuts a PyPI release: never merge onto a red release; after each merge confirm `release` (publish.yml) is green.
- Required check names must not change: `mutation`, `patch-coverage`, `lint`, `tests (<os>, <py>)`, `install-smoke`, `evals`, `bdd`, `onnx-inference` (`.github/required-checks.txt`).
- No required check may be skipped into green. A job with `if: always()` must inspect its `needs` results itself.
- `publish.yml` stays cache-free and still fires only on a successful `ci` **push** run on `main`.
- Diff gate: ≥80% killed over in-scope mutants, `killed / (total - skipped)` with mutmut's own `status_by_exit_code`; fewer than 10 in-scope mutants → any non-killed, non-skipped mutant fails.
- Diff scope: functions in `boost_cli/core` whose mutmut hash changed (or are new) vs the merge base, plus direct callers from `mutmut-stats.json` `function_dependencies`. Every mutant of those functions counts, including old survivors.
- Full-run triggers on a PR: `setup.cfg [mutmut]` section, `requirements/mutation-tools.txt`, any `scripts/mutation_*.py`, any `jobs.mutation*` entry in `.github/workflows/ci.yml`, `pyproject.toml [tool.pytest.ini_options]` (plan's call: it changes how every test runs, mutmut treats it as a global config change). Test-only changes do not run the gate.
- Diff shards: `min(16, ceil(N / 1500))`; full run stays 24 shards.
- Nightly: `ci` on `schedule: cron "30 9 * * *"` (09:30 UTC daily; clear of the 04:00–08:00 UTC weekly crons) and `workflow_dispatch`; both run only the mutation jobs, always in full mode.
- Proven-tree skip on `main` push requires all of: an associated PR whose head commit's tree equals the merge commit's tree, a `ci` `pull_request` run on that head with conclusion `success`, and the most recent completed `schedule`/`workflow_dispatch` `ci` run on `main` concluding `success`. Any error or missing fact → full run.
- No PR run ever writes a mutation baseline or cache. This plan writes none at all (whole-codebase incremental is a non-goal).
- `mutation-weights` is uploaded only from full-mode runs; `mutation-weights-refresh.yml` accepts triggering events `push` and `schedule`.
- `-n auto` lives in `ci.yml` commands only, never in `pyproject.toml` addopts (mutmut runs pytest too).
- New `.py` files: run `python3 scripts/add_spdx_headers.py`. Workflow edits: update `.github/zizmor.yml` anchors until `tests/unit/test_zizmor_ignores_still_anchor.py` passes.
- Local test runs use a sandbox HOME: `export HOME=$TMPDIR/boost-home` then `mkdir -p $HOME`, and a per-worktree `TMPDIR`.
- Commits: `git commit -s`, ending with the session's Co-Authored-By / Claude-Session lines.

## Review Focus

1. **A `tests` cell fails or is cancelled.** `patch-coverage` must fail (missing `coverage-report` artifact), never skip. Pinned by Task 2's workflow test.
2. **The planner fails, or its plan artifact is missing.** `mutation` must be red. Zero shards is a pass only when the planner succeeded and said `none` or an empty diff scope. Pinned by Task 1's and Task 7's workflow tests.
3. **Awkward diffs:** a deleted function or file (no mutants, nothing to gate), a new file, a rename (`--no-renames` makes it delete + add), an edit inside a class method (mangled `xǁClassǁmethod` names must survive the shell; `set -f` stays), and an `__init__.py` edit (no addressable pattern; ignored). Pinned by Task 5's tests.
4. **Proven-tree facts unavailable:** a direct push with no PR, a PR run that was cancelled or re-run, API errors or rate limits, and no nightly yet. Each must give `skip=false` with a reason. Pinned by Task 9's tests.
5. **xdist side effects:** workers sharing a HOME or TMPDIR, or `-n` leaking into mutmut's pytest. Pinned by Task 2 (three clean `-n auto` runs, and a test that `pyproject.toml` addopts carry no `-n`).

### Task 6: diff plan and the diff gate

**Files:**

- Modify: `scripts/mutation_diff.py`, `scripts/mutation_plan.py`
- Test: `tests/unit/test_mutation_diff.py`, `tests/unit/test_mutation_plan.py`

**Interfaces:**

- Consumes: Task 5's functions; Task 1's plan schema.
- Produces: `mutant_counts(path: str, src: str) -> dict[str, int]` (mangled → count, via `mutate_file_contents`).
- Produces: `pack_functions(counts: dict[str, int], ms_per_mutant: dict[str, float], per_shard: int = 1500, cap: int = 16) -> list[list[str]]`. Shard count is `min(cap, ceil(sum(counts.values()) / per_shard))`. Packing is longest-first by `counts[f] * ms_per_mutant.get(f, mean)` and deterministic (ties broken by name). Each shard is a list of qualified functions.
- Produces: `pattern(qualified: str) -> str` = `qualified + "__mutmut_*"`.
- Produces: `mutation_plan.py diff --base SHA --head SHA --stats PATH [--shadow] --out PLAN`.
  - With full-run reasons: same as `full`, reasons recorded.
  - Empty scope: `gate_set` is `"diff"` with `sets.diff.shards == []`.
  - Otherwise `sets.diff = {"shards": [[pattern...]...], "mutants": N, "functions": [...]}` and `gate_set` is `"diff"`.
  - `--shadow` additionally adds `sets.full` (24 shards) and sets `gate_set` to `"full"`.
- Produces: `Verdict(killed: int, denominator: int, unrun: list[str], survivors: list[str], timeouts: list[str])` and `score(codes: dict[str, int | None]) -> Verdict`, mapping statuses with `mutmut.stats.status_by_exit_code`.
- Produces: `passes(v: Verdict, min_pct: float = 80.0, small: int = 10) -> bool`. False if `unrun`. If `denominator < small`, true only when `killed == denominator`; otherwise `100 * killed / denominator >= min_pct`. A zero denominator with nothing unrun passes.
- Produces: `mutation_diff.py gate --plan PLAN --source DIR --prefix mutation-diff-shard- [--min 80] [--small 10]`. Exit 0 pass, 1 fail, 2 unrun or missing shard. Writes `$GITHUB_STEP_SUMMARY` (score line plus every survivor) and one `::warning file=…,line=<def line>::` per surviving function listing its first three survivor names.
- Produces: `mutation_diff.py compare --plan PLAN --full-source DIR --diff-source DIR`. Prints `agree N, disagree M, excluded-timeouts K` and lists each disagreement. Exit 1 on M > 0.
