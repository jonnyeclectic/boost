<b><code>run --print</code>'s provenance banner names the wrong command.</b> The first line of the emitted runner reads <code># Generated by `boost adapt brainstorming --to agents-sdk`. Do not edit by hand.</code> &mdash; but that command produces a 9-line Agent module, while this is a 55-line runner with <code>_boost_brain</code>, <code>read_file</code>/<code>list_dir</code>/<code>grep</code> tools and <code>Runner.run_sync</code>. The banner's stated purpose is provenance (&ldquo;Do not edit by hand&rdquo; &mdash; regenerate instead), and the command it names cannot regenerate the file: <code>adapters.render_runner</code> (<code>boost_cli/core/adapters.py:539-562</code>) returns <code>render_agents_sdk(&hellip;)</code> plus tools and a main, inheriting the agents-sdk banner from line 267 verbatim. Fix: in <code>render_runner</code>, replace the first line with <code># Generated by `boost run NAME [TARGET] --print`. Do not edit by hand.</code> (including TARGET when given), and add a unit test asserting the runner's banner names <code>boost run</code>. No flag or summary changes, so docs/commands.html needs no regeneration. Found by the 2026-08 CLI audit (cluster <code>run-print-banner</code>); repro in the audit log.
