Reliability & Correctness

State that survives interrupts, concurrent loops, and bad input.

8 items
BOOST-001Next

Atomic, corruption-safe lock-file writes

read() returns an empty skeleton on any JSON error and write() is a bare write_text. An interrupted or concurrent write truncates the lock — the next set_skill() then permanently drops every prior install record while store dirs linger as orphans. Write to a temp file + os.replace(), and tell "empty" apart from "corrupt".

BOOST-002Next

Fix self-update version detection (dead branch)

cmd_self_update greps __init__.py for a __version__ = "…" literal, but the constant is _detect_version() (setuptools-scm — no literal). The regex never matches, so it reports "already up to date" even after a pull brings a newer tag. The success path is unreachable.

BOOST-003Proposed

Atomic skill install (temp-dir swap)

_copy_skill does rmtree(dest) then copytree(); an interrupt between the two leaves a missing or half-copied skill, and the lock is written afterward — so a mid-copy failure leaves store and lock disagreeing. Copy to a temp dir and atomically swap into place.

Performance

Fewer disk reads and cheaper walks on the hot search / sync paths.

4 items
BOOST-009Next

Memoize config.load() in-process

Every config.get() re-reads config.json and runs a recursive deepcopy of DEFAULTS. It's called all over hot paths — ai.enabled, per-skill enabled_agents in sync loops, log-level and policy checks — so one command triggers dozens of full reads + deep-copies. Cache the load, invalidate on save.

core/config.py:80–102
BOOST-010Proposed

Cache the catalog entry-set across RAG queries

rag.retrieve() calls all_entries(), which reads & json.loads every tap cache on every search to build the live map (the BM25 index is mtime-cached, the entry set is not). Memoize the entry set on cache mtime the same way.

BOOST-011Proposed

Security

BOOST-020Next

End-of-options -- guard on git commands

clone_shallow/fetch/reset pass the URL & ref as positionals with no -- separator, so a value starting with - is parsed as a git option. parse_spec constrains most URL shapes, but adding -- before positionals and rejecting ext::/file::/fd:: transports closes the argument-injection surface as defense-in-depth.

Testing & CI

Keep the four gates green — and the release pipeline honest.

7 items
BOOST-021Next

Pin CI dev-tool versions

Every job installs ruff mypy pytest pytest-cov coverage mutmut unpinned. Since all four gates are zero-tolerance and every merge to main cuts a PyPI release, a new ruff rule or mypy release can turn a no-op commit red and stall releases. Add a requirements-dev.txt / constraints file.

ciComplexity SImpact High★★★★☆
.github/workflows/ci.yml:19,48,93 · Makefile:13
BOOST-022Proposed

De-flake the mutation gate on slow runners

Score is killed / (total − skipped) with timeout mutants counting as survivors. A loaded CI runner inflates timeouts and can drop the score below 80% with no code change, blocking release. Exclude timeouts from the denominator or raise mutmut's per-test timeout.

Test the generator & gate scripts
