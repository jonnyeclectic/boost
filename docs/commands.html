Install & lifecycle

installpkg

Install a skill from a tap registry

boost install [--force] [--path P] [--agent A] [--scope {user,project}] [--local] [--global] [--dry-run] [--no-deps] [--no-mcp] NAME [NAME ...]
Arguments
NAMEskill name, optionally qualified as tap:skill
Options
--forcereinstall even if already installed or pinned
--path Ppick which copy to install when one registry ships the name more than once (see the paths that error lists); may be a trailing path segment
--agent Alink only into this agent (repeatable)
--scope {user,project}install into your user config (default) or the current repo (project)
--localinto this repo, committable (= --scope project)
--globalinto your user config (= --scope user, default)
--dry-runshow what would happen without changing anything
--no-depsinstall only the named skills, not their `requires:`
--no-mcpdon't offer to register MCP servers a skill declares

reindexfind

Build/refresh the full-content search index

boost reindex [--force] [--dense] [--export-shard TAP] [--import-shard FILE] [--fetch-shards] [--json]

Build or refresh the full-content search index

Options
--forcereindex every tap, ignoring cached commits
--densealso embed chunks into the opt-in dense vector store (needs the `rag` extra; no API key required)
--export-shard TAPwrite TAP's prebuilt vectors to stdout as JSON, for publishing so others need not re-embed them
--import-shard FILEmerge a prebuilt vector shard, skipping the embed cost; refused unless it matches this store's backend and the tap's current commit
--fetch-shardsdownload and import published vectors for every tap that has them, instead of embedding locally
--jsonmachine-readable output

Taps & registries

taptap

Add a GitHub repo as a skill registry

boost tap [--defaults] [--catalog] [--type {skill,rule,workflow}] [--category CATEGORY] [--limit N] [--include-lists] [--dry-run] [--curated] [--at SHA] [--jobs N] [spec]
Arguments
specowner/repo, a git URL, or a local directory
Options
--defaultstap the recommended public registries
--catalogtap from the bundled curated registry catalog
--type {skill,rule,workflow}with --catalog: restrict to one item type
--category CATEGORYwith --catalog: restrict to one category
--limit Nwith --catalog: only the top N registries by est. size
--include-listswith --catalog: also tap awesome-list/index repos
--dry-runwith --catalog: print what would be tapped, tap nothing
--curatedmark the tap as curated (★ in listings)
--at SHApin the clone to one 40-character commit, as a published vector shard requires
--jobs Nclone this many registries at once (default 8, max 16)
